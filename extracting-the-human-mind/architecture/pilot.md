# 파일럿 서비스 설계 (Q1 실험 앱)

제품 MVP([mvp.md](../overview/mvp.md))와 별개로, 친구를 초대해 실제 데이터를 모으고 [Q1](../research/open_questions.md)을 판정하는 연구용 웹 서비스다. 활용 모드(상담·분석·시뮬레이션)는 파일럿 범위 밖이다.

## 참가 흐름
> 탐색중

1. **초대 코드 → 온보딩**: 실명 대신 닉네임. 참가자 토큰은 httpOnly 쿠키, 기기 이동은 재접속 코드.
2. **동의**: 먼저 '무엇을 하게 되나요'(5~7주·약 4~6시간, 결과 없음, 힘든 주제와 비워 두기, 읽는 사람)를 보이고, [실험 주의서](../operations/experiment_ethics.md)의 동의 문구·용도별 토글(분석·시뮬레이션·검증·연구 수확, 기본 꺼짐·철회 가능)을 그대로 쓴다. 과제 화면마다 위쪽에 '잠깐 쉬기'·'힘들 때'(109) 상시 노출.
3. **arm (i)·(ii) 자유서술**: 배터리보다 *먼저* 받는다(배터리가 점화하면 대조군이 오염됨). (i) 순수 자유 자기개방, (ii) 일반 심화 프롬프트.
4. **arm (iii) 고정 배터리**: 전 참가자 동일 구성·동일 순서 규칙. 세션을 나눠 진행([principles](../overview/principles.md) §1-0-5 피로 관리). 배터리 뒤 자유연상 하루, 그다음 14일 ESM(그 안에 DRM 2회).
5. **hold-out 프로브**: 배터리 완료 수일 뒤 별도 세션. 참가자에게 예측을 보여주지 않는다(L1 무결성, [validation_mode](../validation/validation_mode.md) §1-0). 문항 초안은 [pilot_probe_set](../validation/pilot_probe_set.md).
6. **재검사**: 1~2주 뒤 같은 프로브 재제시 → 안정 천장(도메인당 앵커 ≥ 8).
7. **오프라인 분석**: 연구자가 내보낸 데이터로 arm별 단일 프롬프트 예측 → 채점 → 정규화 정확도(바닥차감). 참가자 ≥ 5명이면 라인업(A2).

## Q1 설계 쟁점
> 탐색중

- **분량 매칭**: B-08은 본인 단어수·소요시간 ±10% 매칭을 요구하지만, 자유서술은 배터리보다 *먼저* 받아야 해서(점화 차단) 수집 시점엔 목표 분량을 모른다. 그래서 자유서술 중 30초마다 길이 스냅샷(활성 시간·글자 수·어절 수)을 측정 메타데이터로 남긴다 — 분석 때 비교 대상의 단어수·시간을 정확히 맞출 수 있다(매칭 방향은 「사용자 결정」 표).
- **부담**: 배터리만 현실적으로 약 2.6~4.6시간(2026-10-02 사용성 감사 추정 — 삼항·래더링 세션과 인생 장면·EFT 세션이 표시 시간의 약 두 배), 전체는 ESM 14일과 프로브 두 번을 포함해 5~7주. 이탈 위험이 크므로 진행률·재개·세션 분할을 1급 기능으로 두고, 동의 전에 시간 부담을 밝힌다.
- **게이트 이후 추가 모듈**: 런칭 뒤에 넣는 모듈의 데이터는 Q1 arm (iii) 밖의 추가 수집으로 분리 표기한다.

## S1·S2 파일럿 기본값
> 탐색중

모듈 문서가 비워 둔 곳을 S1·S2 구현이 임시로 채운 값. 코드는 서비스 저장소의 한 곳(`web/lib/modules`, 순서는 `api/app/battery.py`)에 모여 있어 바꾸기 쉽다. **런칭 전에 확정한다**(런칭 게이트).

| 항목 | 임시 기본값 | 문서의 빈칸 |
|---|---|---|
| 은유·문장 완성 카드 | 자기 덱 9장, 문장 완성·은유 교차 고정 순서 | 무작위 순서 규칙이 모호("같은 유형 연속 회피") |
| 판단 시나리오 | 일 1번(방향성)·관계 1번(비밀과 신뢰) 2개 고정 | 도메인 내 어느 시나리오인지, 자기 도메인 풀 없음, 도메인 C 매핑 없음 |
| 애착 서사 줄기 | A(연애)·C(우정) 2개 고정 | "1~2개"만 말함. B(가족)의 마중물은 중립 줄기에 없는 단서(전화·냉랭함)를 더해 제외 |
| 가치 할당 | 가치 2개 이상(필수)·최대 6개, 같은 말 두 번 막음 / 할당 발문 "이 상황에서 각각이 당신에게 얼마나 중요한지에 따라 100점을 나눠 주세요…"(행 순서로 저장, ±10·±1·'남은 점수 모두') / 1위·최하위 동점이면 참가자가 그 안에서 고름 / allocations는 입력 순서 보존 | 할당 화면 문구·동점 규칙 없음 |
| CCRT | 관계 태그 발문 "…사람 한 명을 떠올려 주세요(앞 장면과 다른 사람). 그 사람은 당신에게 어떤 관계인가요?" / 장면 3개로 완료(더 적기는 선택) / 반복성 = {있다·없다, 짧은 서술} / 관계 유형 3지(일·학업으로 아는 사이·가족·연인·친구 같은 사적인 사이·섞여 있음) / '[ ]게' 틀 대신 질문 | 관계 태그 발문 없음, "도메인당 최소 3장"과 5~10분 추정 충돌 |
| CIT | `data_type: retrospective_self_report`, 도메인 태그는 마지막 | 문서 안 `self_report`/`retrospective_self_report` 혼용 |
| 두려운 자기 | `raw_early_warning`은 문자열(문서 YAML은 목록), 마중물은 입력칸 위 고정 문장(답에 안 들어감), 앞 답은 질문 위에 인용 | 단일 신호 발문 vs 목록 필드 |
| EFT | '5년 뒤' 깜빡이 타이머 미적용(ui_ux §1·§6과 충돌), '잘 모르겠어요' = 빈 답 + `skipped` 메타, §1-3은 근미래 *장면* 질문 | 타이머 성격·건너뛰기 저장 값 없음 |
| 배터리 순서 | 애착 서사 → TAT → 은유 → 판단 → 가치 할당 → 자기–타자 → 클린 랭귀지 → CIT → CCRT → 두려운 자기 → 삼항 → 래더링 → 인생 장면 → EFT. 투사 이야기(애착 서사·TAT)를 먼저, 그다음 문장 완성 덱, 모두 가치를 이름 붙이는 모듈보다 앞에; 판단 시나리오는 가치 할당 앞(결정 기준이 방금 이름 붙인 가치에 점화되지 않게, 2026-10-02 감사 B4); TAT와 삼항은 멀리, 앞 모듈 답을 읽는 모듈은 그 뒤에, 클린 랭귀지는 은유 덱과 멀리, 인생 장면–EFT는 붙여서 | 고정 순서 없음(피로 관리 원칙·의존성 도표만) |
| 짧은 답 확인 | 빈 답에만("이 질문은 비워 두고 넘어갈까요?", 같은 무게의 두 버튼), 자유서술 arm 포함 모든 서술 단계에 같게. 짧은 답 확인·권장 시간 안내·글자 수 표시는 없음 | 적용 범위 없음 |
| Q1 arm 문구 | (i) "당신에 대해 쓰고 싶은 것을 자유롭게 적어 주세요. 주제도 순서도 정해져 있지 않아요." 시간은 안내에 한 번(15분쯤), (ii) 이름 '질문 따라 쓰기', 일반 심화 4문항(힘들었던 순간·중요한 것·사람들과·앞으로) 각 4분쯤. 화면에 시간·어절 표시 없음(30초 스냅샷은 조용히 기록) | arm 발문은 예시("힘들었던 순간을 얘기해줘") 하나뿐 |
| TAT (S2) | 6장면 전부 A→B→C 고정 순서, ID `A-1`~`C-6`, 단일 서술창에 마중물 없음, 세션 분할은 S5 전까지 순서로만 | 장면 순서·ID·도입 안내 없음, 단계별 마중물은 폼 분할 전제 |
| 자기–타자 (S2) | 타깃 = 가치 할당 1위, 우회 프롬프트는 제출 전 힌트, `target_from_event` 저장 | 삼항 S 1위와 가치 할당 1위 중 고르는 규칙 없음 |
| 삼항 (S2) | 도메인 관계 고정, 24라운드 고정 표(AG(2,3) 두 벌, 12라운드까지 모든 쌍 1회), 패스 15초, 살리언시·평정 발문 작성, 원소·E-id 저장 필드 추가 | 24블록 표·참가자 발문·원소 저장 필드 없음 |
| 인생 장면 (S2) | 앵커 = 가치 할당 1위 하나 × 빛남·훼손 → 2장면, 서술 → 시기 이름 → 인물 링킹(E4~E9) → 도메인, 훼손 장면·기원 카드·타임라인은 확인 후 건너뛰기 가능, 타임라인은 버튼 정렬·별도 엔트리, `high_point`·`trigger_value` 추가 | 앵커 개수·매핑, 긍정 장면 값, 타임라인 저장 방식 없음 |

## S3 파일럿 기본값
> 탐색중

S3(동적 모듈·가명화) 구현이 문서의 빈칸을 임시로 채운 값(2026-10-02 감사로 다시 씀). 코드는 서비스 저장소 `api/app/pseudonym.py`, `web/lib/names.ts`, `api/app/llm.py`, `api/app/dynamic/`에 모여 있다. **런칭 전에 확정한다.**

## 스택·배포
> 탐색중

- **저장소 구조**: 비공개 저장소 `YiTanJang/ethm-pilot` — `api/`(FastAPI·SQLAlchemy), `web/`(Next.js App Router·TypeScript), `deploy/k8s`(매니페스트), CI. 코드는 OKF 규칙 밖.
- **DB**: SQLite(WAL) + PVC, API 단일 레플리카. 참가자 수십 명 규모에 충분하고 백업은 파일 복사. raw 테이블은 append-only(수정·삭제는 참가자 본인 "내 데이터 삭제"만).
- **이미지**: GitHub Actions가 테스트 후 빌드해 비공개 GHCR 패키지(`ghcr.io/yitanjang/ethm-pilot/{api,web}`)에 푸시, k3s가 `ghcr-pull` 시크릿으로 pull. 이미지에 비밀값·데이터 없음.
- **노출**: Cloudflare Tunnel(호스트) → `web` NodePort 30380. API는 NetworkPolicy로 `web` 파드에서만 접근.
- **LLM**: 추출 단계 LLM은 동적 모듈(래더링·클린 랭귀지)에만. 외부 전송 전 2계층 가명화([architecture.md](architecture.md) §2 Module 1). 예측·채점은 앱 밖(오프라인).
