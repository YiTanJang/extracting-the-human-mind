# 파일럿 서비스 설계 (Q1 실험 앱)

제품 MVP([mvp.md](../overview/mvp.md))와 별개로, 친구를 초대해 실제 데이터를 모으고 [Q1](../research/open_questions.md)을 판정하는 연구용 웹 서비스다. 활용 모드(상담·분석·시뮬레이션)는 파일럿 범위 밖이다.

## 참가 흐름
> 탐색중

1. **초대 코드 → 온보딩**: 실명 대신 닉네임. 참가자 토큰은 httpOnly 쿠키, 기기 이동은 재접속 코드.
2. **동의**: [실험 주의서](../operations/experiment_ethics.md)의 동의 문구·용도별 토글(분석·시뮬레이션·검증·연구 수확, 기본 꺼짐·철회 가능)을 그대로 쓴다. 위기 상황 안내 상시 노출.
3. **arm (i)·(ii) 자유서술**: 배터리보다 *먼저* 받는다(배터리가 점화하면 대조군이 오염됨). (i) 순수 자유 자기개방, (ii) 일반 심화 프롬프트.
4. **arm (iii) 고정 배터리**: 전 참가자 동일 구성·동일 순서 규칙. 세션을 나눠 진행([principles](../overview/principles.md) §1-0-5 피로 관리). 마지막 단계는 14일 ESM(그 안에 DRM 2회).
5. **hold-out 프로브**: 배터리 완료 수일 뒤 별도 세션. 참가자에게 예측을 보여주지 않는다(L1 무결성, [validation_mode](../validation/validation_mode.md) §1-0).
6. **재검사**: 1~2주 뒤 같은 프로브 재제시 → 안정 천장(도메인당 앵커 ≥ 8).
7. **오프라인 분석**: 연구자가 내보낸 데이터로 arm별 단일 프롬프트 예측 → 채점 → 정규화 정확도(바닥차감). 참가자 ≥ 5명이면 라인업(A2).

## Q1 설계 쟁점
> 탐색중

- **분량 매칭**: B-08은 본인 단어수·소요시간 ±10% 매칭을 요구하지만, 자유서술은 배터리보다 *먼저* 받아야 해서(점화 차단) 수집 시점엔 목표 분량을 모른다. 그래서 자유서술 중 30초마다 길이 스냅샷(활성 시간·글자 수·어절 수)을 측정 메타데이터로 남긴다 — 분석 때 비교 대상의 단어수·시간을 정확히 맞출 수 있다(매칭 방향은 「사용자 결정」 표).
- **부담**: 16종 전체 ≈ 2.5시간 + ESM 14일. 이탈 위험이 크므로 진행률·재개·세션 분할을 1급 기능으로 둔다.
- **게이트 이후 추가 모듈**: 런칭 뒤에 넣는 모듈의 데이터는 Q1 arm (iii) 밖의 추가 수집으로 분리 표기한다.

## S1·S2 파일럿 기본값
> 탐색중

모듈 문서가 비워 둔 곳을 S1·S2 구현이 임시로 채운 값. 코드는 서비스 저장소의 한 곳(`web/lib/modules`, 순서는 `api/app/battery.py`)에 모여 있어 바꾸기 쉽다. **런칭 전에 확정한다**(런칭 게이트).

| 항목 | 임시 기본값 | 문서의 빈칸 |
|---|---|---|
| 은유·문장 완성 카드 | 자기 덱 9장, 문장 완성·은유 교차 고정 순서 | 무작위 순서 규칙이 모호("같은 유형 연속 회피") |
| 판단 시나리오 | 일 1번(방향성)·관계 1번(비밀과 신뢰) 2개 고정 | 도메인 내 어느 시나리오인지, 자기 도메인 풀 없음, 도메인 C 매핑 없음 |
| 애착 서사 줄기 | A(연애)·C(우정) 2개 고정 | "1~2개"만 말함. B(가족)의 마중물은 중립 줄기에 없는 단서(전화·냉랭함)를 더해 제외 |
| 가치 할당 | 가치 2개 이상(필수)·4개 권장(부드러운 확인)·최대 6개 / 할당 화면 문구는 §2-2 서술에서 작성 / 1위·최하위 동점: 1위=먼저 적은 것, 최하위=나중에 적은 것 / allocations는 입력 순서 보존 | 할당 화면 문구·동점 규칙 없음 |
| CCRT | 관계 태그 입력 안내 추가("이름은 적지 말고 관계만") / 장면 3개(도메인 무관)로 완료 / 반복성 = {있다·없다, 짧은 서술} / 도메인 태그는 문서의 3지 / "실명으로 떠올리라" TIP은 미적용 | 관계 태그 발문 없음, "도메인당 최소 3장"과 5~10분 추정 충돌, 저장 전 가명화 미구현 |
| CIT | `data_type: retrospective_self_report`, 도메인 태그는 마지막 | 문서 안 `self_report`/`retrospective_self_report` 혼용 |
| 두려운 자기 | `raw_early_warning`은 문자열(문서 YAML은 목록), 마중물의 대괄호 제거 | 단일 신호 발문 vs 목록 필드 |
| EFT | '5년 뒤' 깜빡이 타이머 미적용(ui_ux §1·§6과 충돌), '잘 모르겠다' = 빈 답 + `skipped` 메타 | 타이머 성격·건너뛰기 저장 값 없음 |
| 배터리 순서 | 은유 → 애착 서사 → TAT → 가치 할당 → 자기–타자 → 판단 → 클린 랭귀지 → CIT → CCRT → 두려운 자기 → 삼항 → 래더링 → 인생 장면 → EFT. 투사 모듈을 가치를 이름 붙이는 모듈보다 앞에, TAT와 삼항은 멀리, 앞 모듈 답을 읽는 모듈은 그 뒤에, 클린 랭귀지는 은유 덱과 멀리·무거운 모듈 바로 뒤는 피해서, 인생 장면–EFT는 붙여서 | 고정 순서 없음(피로 관리 원칙·의존성 도표만) |
| 짧은 답 확인 | 서술형 단계에만(문장 완성·목록·태그 제외) | 적용 범위 없음 |
| Q1 arm 문구 | (i) "당신은 어떤 사람인가요?…" 15분 권장, (ii) 일반 심화 4문항(힘들었던 순간·중요한 것·사람들과·앞으로) 각 4분 권장 | arm 발문은 예시("힘들었던 순간을 얘기해줘") 하나뿐 |
| TAT (S2) | 6장면 전부 A→B→C 고정 순서, ID `A-1`~`C-6`, 단일 서술창에 마중물 없음, 세션 분할은 S5 전까지 순서로만 | 장면 순서·ID·도입 안내 없음, 단계별 마중물은 폼 분할 전제 |
| 자기–타자 (S2) | 타깃 = 가치 할당 1위, 우회 프롬프트는 제출 전 힌트, `target_from_event` 저장 | 삼항 S 1위와 가치 할당 1위 중 고르는 규칙 없음 |
| 삼항 (S2) | 도메인 관계 고정, 24라운드 고정 표(AG(2,3) 두 벌, 12라운드까지 모든 쌍 1회), 패스 15초, 살리언시·평정 발문 작성, 원소·E-id 저장 필드 추가 | 24블록 표·참가자 발문·원소 저장 필드 없음 |
| 인생 장면 (S2) | 앵커 = 가치 할당 1위(+ 래더링 종착 가치, S3) × 빛남·훼손 → 4장면, 기원 카드·타임라인은 건너뛰기 가능, 타임라인은 버튼 정렬·별도 엔트리, `high_point`·`trigger_value` 추가 | 앵커 개수·매핑, 긍정 장면 값, 타임라인 저장 방식 없음 |

## S3 파일럿 기본값
> 탐색중

S3(동적 모듈·가명화) 구현이 문서의 빈칸을 임시로 채운 값. 코드는 서비스 저장소 `api/app/pseudonym.py`, `api/app/llm.py`, `api/app/dynamic/`에 모여 있다. **런칭 전에 확정한다.**

| 항목 | 임시 기본값 | 문서의 빈칸 |
|---|---|---|
| 가명화 1계층 | 정규식(이메일·전화번호·주민등록번호) + 참가자 이름 목록을 저장 직전·Claude 전송 직전에 자동 치환. 바뀌는 건 일치한 글자뿐(조사·띄어쓰기 그대로). 토큰 `[Person_A]`·`[Org_A]`·`[Email_A]`·`[Phone_A]`·`[ID_A]`, 참가자별·등장 순 | 토큰 형식이 문서마다 다름(`[Name_A]`·`[Person_A]`·`[Company_B]`) |
| 가명화 2계층 | Claude가 아닌 로컬 규칙 탐지기(이름 뒤 씨·님, 붙은 언니·형·선배, '○○이가/이랑', 영문 이름, 회사·학교 접미사)가 후보만 제시. 후보가 있을 때만 저장 직전 확인 화면(기본 미선택, 직접 추가 가능). 확인한 이름은 목록에 들어가 이후 1계층이 자동 처리 | NER 방법·확인 시점 없음. 탐지기가 못 잡는 맨이름('지영 그랬다')은 참가자가 직접 추가하거나 다음에 목록으로 잡힘 |
| 이름 목록 보관 | 키(`PILOT_PSEUDONYM_KEY`)로 암호화해 DB에, 참가자 삭제 시 함께 삭제. 원래 이름은 본인 화면·본인 내보내기에서만 되돌림. 연구자 내보내기·Claude에는 토큰만 | 목록 위치·열람 범위·가역성 없음 |
| 가명화 밖 사본 | 임시저장 초안은 가명화 전 버퍼(본인 내보내기에만, 과제 완료 시 삭제), 노드 안 백업은 14일 보관 | 초안·백업 언급 없음 |
| 삼항 원소 | 원소 입력 저장 전 E4~E9를 이름 후보로 함께 제시(관계 단어는 그냥 두면 됨) | 원소가 실명일 때 처리 없음 |
| Claude 호출 | 모델 `claude-opus-5-5`, JSON 스키마 구조화 출력, 질문은 쓰지 않고 고르기만, 모든 시도를 `llm_calls`에 기록(가명화된 요청·응답·판정·지연), 검증 뒤 표시(스트리밍 없음), API 장애 시 답을 소모하지 않고 다시 보내게 함. 현재 모델은 온도 설정이 없어 '온도 0~0.2'는 고정 템플릿 + 기계 검증으로 대신 | [architecture.md](architecture.md) §2의 '꼬리질문 생성'·온도·SSE |
| 래더링 | 타깃 = S(제시 원소 살리언시 합)·C(Σr², PC1 20% 미만이면 제외)·K(문제 축 \|E1−E2\|≥3과 일치 축 ≤1을 선호 극으로 맞춘 뒤 r ≤ −0.67) 각 1위, 최대 3개, 동점은 앞 라운드, E2 = 4만 제외. 질문은 T1·T2·경계 고정 템플릿이고 Claude는 {slot, stop}만 고름(문서의 질문 생성 프롬프트 대신). 최대 4답, 반복·방어적 회피('그냥'·'모르겠다'만 2번 연속)는 코드 판정, 경계 질문은 terminal_value·max_depth·repetition 뒤 1회. 검증 2번 실패 시 답 전체(30자 이하)를 슬롯으로, 아니면 `unverified` 종료. 그만하기 `user_stop`, 기준 건너뛰기도 기록(`skipped`), 짧은 답 확인 없음, 화면엔 두 극만(해석 문구 없음) | 질문 생성 주체·종착 판정·최대 깊이·검증 실패·중단·축 개수 |
| 클린 랭귀지 | 독립 모듈(문서의 여는 질문), 마중물은 입력칸 안내문. 슬롯 = 이번 인터뷰의 참가자 글 어디서든 어절 첫머리부터 그대로(30자 이하, 가린 표기를 쪼개지 않음). 템플릿은 슬롯 뒤 은/는만 받침에 맞춤. 최대 12턴, Claude가 포화·'없다'로 끝낼 수 있음, 그만하기. 검증 2번 실패 시 '그다음엔 무슨 일이 일어나는가?'. 도메인 general, 여는 답에만 짧은 답 확인 | 슬롯 출처(직전 발화 vs 이미 꺼낸 상징), 조사, 재시도·종료 판정, 배터리 위치 |
| 인생 장면 앵커 | 가치 할당 1위 + 래더링에서 처음 종착 구절(`terminal_slot`)에 닿은 사슬의 그 구절 → 최대 2앵커 4장면 | 래더링에 종착 가치 저장 필드 없음 |

## S4 파일럿 기본값
> 탐색중

S4(ESM·DRM) 구현이 문서의 빈칸을 임시로 채운 값. 코드는 서비스 저장소 `api/app/esm.py`(일정·문항 문구), `api/app/routers/esm.py`, `web/components/engine/Esm.tsx`. **런칭 전에 확정한다.**

| 항목 | 임시 기본값 | 문서의 빈칸 |
|---|---|---|
| ESM 위치 | 배터리 마지막 단계(EFT 뒤). 설정한 다음 날부터 14일 고정 창(한국 시간), 창이 끝나야 단계 완료. arm (iii)에 포함(프로브 전 14일) — 응답 수는 참가자마다 달라 준수율을 공변량으로 | 배터리 순서·arm (iii) 포함 여부·시작 시점 없음 |
| 알림 슬롯 | 참가자가 고른 시각 1~2개(하루 최대 2번), 횟수 0~2는 언제든 바꾸고 바꾼 이력을 남김(`esm_settings_log`). 무작위 푸시 없음 | 시각 범위·조용한 시간 없음 |
| 만료 | 슬롯 3시간 뒤 만료, 3시간 넘게 놓친 슬롯은 나중에 만들지 않음. 발송·만료·응답 시각은 raw 밖 `esm_pings`에 | 만료·놓친 알림 처리 없음 |
| 알림 | Web Push(VAPID). 알림 문구는 질문 없이 "잠깐, 지금 기록할 시간이에요."만. 아이폰은 홈 화면에 추가한 앱에서만(iOS 16.4+). 알림을 못 켜도 앱 안에서 기록 가능. 캘린더 연동 트리거·OS 위젯은 파일럿에서 뺌 | 알림 채널·문구·iOS 조건·대체 수단 없음 |
| 슬롯 문항 | 문서 문구만: "지금 스트레스 지수는?"·"지금 에너지는?"(1~5, 끝 표시 '1 낮음·5 높음')·"오늘 가장 마음이 쓰였던 순간은?"(선택). 행동 문항은 '그 회의'를 전제해 슬롯에선 뺌 | 문항 조합·순서 없음, 행동 지표가 예시 하나뿐 |
| "방금 일 있었어" | 행동 문항을 "방금 그 일에서 …"로 바꿔 씀('해당 없음' 가능) + "한 줄로 덧붙이면?" + 스트레스 + 사후 도메인 질문(principles §1-2 문구, General 포함). 하루 2회 상한과 별개 | 직접 기록의 문항 없음 |
| DRM | 창 8일째·14일째 두 번, 각각 '어제'를 재구성(그날만 가능). 장면별 '무엇을 했는가, 누구와 있었는가'·'그때 무엇을 느꼈는가'·강도 1~5·'한 줄 핵심'(`raw_core`), 하루 요약 + 하루 스트레스·에너지(문서의 '하루 전반 정서 1~5' 대신 ESM과 같은 척도). ESM 응답은 보여 주지 않음 | 시점('당일 말' vs '어제')·빈도('하루 1회' vs '저빈도')·척도 불일치 |
| 저장 | ESM 응답 1회 = raw 1건(`trigger: fixed_slot`·`self_initiated`, `ts` 한국 시간, 문항별 `prompt`·`scale`·`raw_choice` 또는 `raw_text`), DRM 1회 = raw 1건(`method: drm`, `reconstructed_date`) | 문항별 행 vs 응답 단위, 한 줄 필드 없음 |

## 스택·배포
> 탐색중

- **저장소 구조**: 비공개 저장소 `YiTanJang/ethm-pilot` — `api/`(FastAPI·SQLAlchemy), `web/`(Next.js App Router·TypeScript), `deploy/k8s`(매니페스트), CI. 코드는 OKF 규칙 밖.
- **DB**: SQLite(WAL) + PVC, API 단일 레플리카. 참가자 수십 명 규모에 충분하고 백업은 파일 복사. raw 테이블은 append-only(수정·삭제는 참가자 본인 "내 데이터 삭제"만).
- **이미지**: GitHub Actions가 테스트 후 빌드해 비공개 GHCR 패키지(`ghcr.io/yitanjang/ethm-pilot/{api,web}`)에 푸시, k3s가 `ghcr-pull` 시크릿으로 pull. 이미지에 비밀값·데이터 없음.
- **노출**: Cloudflare Tunnel(호스트) → `web` NodePort 30380. API는 NetworkPolicy로 `web` 파드에서만 접근.
- **LLM**: 추출 단계 LLM은 동적 모듈(래더링·클린 랭귀지)에만. 외부 전송 전 2계층 가명화([architecture.md](architecture.md) §2 Module 1). 예측·채점은 앱 밖(오프라인).
